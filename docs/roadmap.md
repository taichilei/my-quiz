# 项目开发路线图 (Roadmap)

本文档定义了 My-Quiz 项目的后续迭代计划，重点关注数据库架构优化、性能提升及功能扩展。

## v1.1: 架构规范化与数据完整性 (近期目标)
**核心目标**：从“数据堆放”转向“结构化管理”，提升系统稳定性。

- [ ] **独立 Exam 实体表**：将题目中的 JSON 试卷信息剥离为独立的 `exams` 表，通过 `exam_id` 进行关联。
- [ ] **强化物理外键约束**：在数据库层面建立 `Question` 与 `AnswerRecord` 之间的外键约束，防止孤立数据的产生。
- [ ] **引入逻辑删除 (Soft Delete)**：集成 `gorm.DeletedAt`，支持题目的误删恢复和历史审计。
- [ ] **规范多选题答案存储**：将 `Answer` 字段统一为 JSON 数组格式，优化多选逻辑校验。

## v1.2: 性能优化与高级检索 (中期目标)
**核心目标**：提升在大数据量下的响应速度和搜索体验。

- [ ] **标签查询优化**：为 `Tags` 字段创建 PostgreSQL `GIN` 索引，支持高效的多标签筛选。
- [ ] **全文检索支持**：引入 PostgreSQL `tsvector` 对题目内容和解析进行中文分词索引，替代低效的 `LIKE` 查询。
- [ ] **统计性能优化**：引入**物化视图 (Materialized View)** 或 Redis 缓存，优化用户正确率和刷题分布的统计效率。

## v2.0: 多用户体系与大数据支持 (远期目标)
**核心目标**：支持多用户协作与大规模并发，提升产品化能力。

- [ ] **完整用户系统 (Users)**：建立用户主表，支持个人偏好设置（如深色模式、当前题库）的云端同步。
- [ ] **答题记录分区化**：针对大规模 `records` 数据，实施数据库**分区表 (Partitioning)** 设计（按月或按用户 ID 分区）。
- [ ] **操作审计日志**：记录所有敏感操作（如批量导入、清空题库），提升系统安全性。

---

## 任务优先级定义
- **P0 (紧急)**: v1.1 中的数据一致性和逻辑删除。
- **P1 (重要)**: v1.2 中的索引优化与全文检索。
- **P2 (扩展)**: v2.0 中的多用户体系与分区表。
