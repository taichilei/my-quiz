# 测试指南

本文档介绍 My-Quiz 项目的后端单元测试和 Postman 接口测试方法。

---

## 一、后端单元测试

### 1.1 测试框架说明

- **测试库**：Go 标准库 `testing`
- **HTTP 测试**：`net/http/httptest` 模拟请求和响应
- **数据库**：SQLite 内存数据库（每个测试独立，避免数据干扰）
- **Web 框架**：Gin 测试模式

### 1.2 运行测试命令

#### 运行所有测试
```bash
cd server
go test ./... -v
```

#### 只运行 handlers 包的测试
```bash
cd server
go test ./handlers -v
```

#### 运行单个测试文件或测试函数
```bash
# 运行认证相关测试
go test ./handlers -run TestAuth -v

# 运行用户接口测试
go test ./handlers -run TestGetMe -v

# 运行题目接口测试
go test ./handlers -run TestGetQuestions -v

# 运行所有以 TestRegister 开头的测试
go test ./handlers -run TestRegister -v
```

### 1.3 测试文件位置

所有测试文件与源码同目录，位于 `server/handlers/`：

| 测试文件 | 说明 | 测试数量 |
|---------|------|---------|
| `auth_test.go` | 认证接口测试（注册、登录） | 6 |
| `user_test.go` | 用户信息接口测试 | 4 |
| `question_test.go` | 题目 CRUD 接口测试 | 10 |
| `exam_test.go` | 考试管理接口测试 | 5 |
| `record_test.go` | 答题记录接口测试 | 5 |
| `session_test.go` | 刷题会话接口测试 | 4 |
| `upload_test.go` | 文件上传接口测试 | 9 |

### 1.4 编写新测试的模板

参考现有测试风格，使用 `setupTestDB()` 函数创建独立的测试数据库：

```go
func TestYourTestName(t *testing.T) {
    gin.SetMode(gin.TestMode)
    db := setupTestDB(t)
    handler := handlers.NewYourHandler(db)

    r := gin.Default()
    r.GET("/api/your-endpoint", middleware.JWTAuth(), handler.YourMethod)

    req, _ := http.NewRequest("GET", "/api/your-endpoint", nil)
    req.Header.Set("Authorization", "Bearer "+yourToken)
    w := httptest.NewRecorder()

    r.ServeHTTP(w, req)

    if w.Code != http.StatusOK {
        t.Errorf("Expected status %d, got %d", http.StatusOK, w.Code)
    }
}
```

## 二、Postman 接口测试

### 2.1 环境配置

1. **导入 Collection**：项目根目录下的 `postman/My-Quiz-API.postman_collection.json`
2. **设置环境变量**：
   - `baseUrl`：`http://localhost:8080`（本地开发）
   - `token`：登录后获取的 JWT token

### 2.2 认证流程（关键步骤）

#### 步骤 1：注册用户

**请求**：
```
POST {{baseUrl}}/api/auth/register
Content-Type: application/json

{
  "username": "testuser",
  "password": "123456",
  "email": "test@example.com"
}
```

**预期响应**（201 Created）：
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 1,
    "username": "testuser",
    "email": "test@example.com",
    "createdAt": 1234567890
  }
}
```

✅ **注意**：`token` 字段在响应的最外层，不是在 `user` 对象内部！

---

#### 步骤 2：设置 Token 环境变量

从注册响应中复制 `token` 值，设置为 Postman 环境变量：
- 变量名：`token`
- 变量值：`eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...`

或者在每个请求的 Headers 中手动添加：
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

---

#### 步骤 3：访问受保护接口

**请求**：
```
GET {{baseUrl}}/api/user/me
Authorization: Bearer {{token}}
```

**预期响应**（200 OK）：
```json
{
  "id": 1,
  "username": "testuser",
  "email": "test@example.com",
  "createdAt": 1234567890
}
```

---

### 2.3 常见错误说明

| 错误 | 原因 | 解决方案 |
|-----|------|---------|
| `401 Authorization header required` | 没有携带 token | 在 Headers 中添加 `Authorization: Bearer <token>` |
| `401 Invalid authorization format` | token 格式错误 | 确保格式是 `Bearer <token>`（注意空格） |
| `401 Invalid or expired token` | token 无效或过期 | 重新登录获取新 token |
| `409 Username already exists` | 用户名重复 | 使用不同的用户名注册 |
| `400 Invalid request body` | 请求参数错误 | 检查 JSON 格式和必填字段 |

## 三、完整测试流程示例

### 3.1 认证接口测试流程

```
1. 注册新用户 → 验证返回 201 和 token
2. 重复注册相同用户名 → 验证返回 409
3. 使用正确密码登录 → 验证返回 200 和 token
4. 使用错误密码登录 → 验证返回 401
5. 使用不存在的用户登录 → 验证返回 401
```

### 3.2 业务接口测试流程

```
1. 注册用户获取 token
2. 携带 token 获取用户信息 → 验证返回 200
3. 携带 token 更新用户邮箱 → 验证返回 200
4. 不带 token 访问题目列表 → 验证返回 401
5. 携带 token 访问题目列表 → 验证返回 200
6. 携带 token 创建考试 → 验证返回 201
7. 携带 token 创建题目 → 验证返回 201
8. 携带 token 创建答题记录 → 验证返回 201
```

## 五、注意事项

1. **测试隔离**：每个测试使用独立的 SQLite 内存数据库，测试之间不会互相影响
2. **Token 有效期**：JWT token 默认有效期 7 天，测试时不需要频繁重新登录
3. **密码加密**：密码使用 bcrypt 加密存储，数据库中不会保存明文密码
4. **Header 格式**：`Authorization` header 必须是 `Bearer <token>` 格式，Bearer 首字母大写，中间有空格
